工单自动化编排 · 全链路可观测

一张工单，一条可回放、可复盘的执行轨迹

这个项目不再用写死的规则说明代替真实链路，而是把一次标准工单的执行过程拆成七个可观测层次：工单输入、任务拆解、工具调用、工具返回、决策推理、分支跳转与最终汇总。每一步都带角色、时间戳、输入、输出与决策理由，可以暂停、重置或跳到任意一步逐步复盘。

标准轨迹数据在 scripts/trace-data.js，快照落在 tests/snapshots/，页面只负责渲染与回放。

01 · trigger

工单原始输入

Issue 标题、正文、来源、提交者与时间戳，是整条轨迹唯一的输入证据。

02 · plan

任务拆解规划

把工单拆成带依赖顺序的子任务，并标注每个子任务由哪个工具承接。

03 · tool_call

工具调用请求

逐字记录下发的命令与参数：命令、工作目录、文件路径，不做概述改写。

04 · tool_result

工具返回 Payload

工具返回的原始摘录：退出码、耗时与关键输出；失败结果同样保留，不粉饰。

05 · reasoning

Agent 决策推理

判定结论、依据说明与规则命中项，回答“为什么走这一步”。

06 · branch

分支跳转

记录正常推进或异常处置的来源节点、目标节点与处理方式。

07 · summary

最终汇总输出

整体结论、产出物清单与后续动作，形成可复盘的闭环交付。

标准样例：样例工单来自 GitHub Issue #11，标准轨迹完整走完触发 → 评估 → 拆解 → 工具调用 → 异常分支 → 汇总，并随测试产出 JSON 快照供逐字节复现。

回放、暂停、跳到某一步

全部回放交互在 执行轨迹页；页面无 JavaScript 时仍保留静态工单说明。

播放 / 暂停自动回放

自动回放每 1.2 秒推进一步，到达末尾时自动暂停；按钮状态与步数文案同步更新。

上一步 / 下一步单步

逐条前进或回退，到达边界时保持不动；计数显示“当前步 / 总步数”。

重置从头开始

回到第 1 步并停止播放，重新开始一次复盘。

seek跳到某一步

拖动滑杆立即定位到目标步骤，只展示该步及之前的轨迹。

plan 子任务折叠展开

plan 层的每个子任务可展开，查看挂在它下面的 tool_call 与 tool_result，理解依赖关系。

本地运行与测试

项目保持零依赖、零构建。页面脚本使用原生 ES modules，请通过静态服务器访问。

先看标准执行轨迹 
# 运行单元测试，并校验 / 产出标准快照
npm test

# 重新生成标准样例工单与标准执行轨迹快照
npm run snapshots

# 启动零依赖静态服务器（默认 http://localhost:8000）
npm run serve

现代浏览器会阻止 file:// 下加载 ES module，因此导航菜单、规则表、轨迹回放与快照摘要都需要静态服务器；直接双击 index.html 仍可查看 HTML 与样式。完整使用说明见仓库中的 docs/guide.md。
