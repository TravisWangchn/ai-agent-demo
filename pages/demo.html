教学对照：四类任务的简化模拟器

简化模型只演示“规则匹配 → 接受判定 → 决策”，不产生真实工具调用

下面的模拟器用于对照理解规则与接受条件：选择任务类型后，页面在本地计算五阶段结果。它不执行命令、不读写文件；真实的工具调用与原始返回请看 执行轨迹页。

等待触发

选择上方任一任务类型，查看规则匹配、接受判定与最终决策。

注意：“视觉调整”会显示“暂不接受”，这是刻意设计的教学案例。请求只说“更好看一点”，缺少具体页面与元素、目标状态和验收方式；Agent 应要求补充规格，而不是自行替人做设计决策。

怎么读这个演示

  1. 先看工单与轨迹摘要：确认触发来源、步骤总数、七层是否覆盖，以及异常分支发生在哪一步。
  2. 再进轨迹页回放：用播放/暂停、上一步/下一步和滑杆逐条查看 role / timestamp / input / output / reason。
  3. 展开 plan 子任务：在 plan 步骤内展开子任务，查看它下挂的 tool_call 与 tool_result，理解依赖关系。
  4. 最后用模拟器对照：四类任务的简化模拟器只演示规则判定；对比它和真实轨迹，就能看出“教学模型”与“真实执行”的差距。

规则本身在 策略规则页 中完整列出；七层轨迹在整体架构中的位置见 架构页。
