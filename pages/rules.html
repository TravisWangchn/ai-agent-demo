策略规则

规则决定 Agent 的边界

规则不是装饰性的说明文档，而是接受任务前必须逐项核对的依据。下面每一条规则都包含适用场景、示例、接受条件，以及接受后的执行与交付产出。规则命中会以“判定依据”的形式出现在执行轨迹的 reasoning 层，未满足条件时则进入 branch 层说明为何不继续。

规则如何被使用

  1. 先匹配，再判断：任务类型先决定适用规则，然后才检查这条规则的接受条件。
  2. 条件必须全部满足：缺少任意一项，结论就是“要求补充规格”，而不是“先做着看看”。
  3. 规则约束执行范围：即使任务被接受，执行与交付也只能覆盖规则描述的范围，不能顺手改造无关模块。
  4. 规则可以被检验：规则数据由 node:test 校验完整性，页面也提供可视化演示，方便对照。
  5. 规则命中可追溯：在标准执行轨迹中，命中哪条规则、补了什么、为什么走异常分支，都记录在对应步骤的 reason 与 branch 字段里。
