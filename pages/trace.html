字段导读

读一步轨迹，先看角色与时间，再看输入输出，最后用 reason 校验动机

role角色

谁在执行或决策。常见取值：orchestrator（编排与拆解）、worker（执行实现）、github（Issue / PR 操作）、shell（命令执行）、filesystem（读写文件）、node-test（测试）与 git（版本操作）。

timestamp时间戳

这一步实际发生的时刻。页面统一以 YYYY-MM-DD HH:mm:ss UTC 展示，避免本地时区导致截图与复盘不一致。

input输入

这一步接收的结构化输入。对 tool_call 来说，就是下发给工具的指令原文参数；对 reasoning 来说，是参与判断的上下文与规则命中项。

output输出

这一步产出的结构化结果。对 tool_result 来说，包含 exitCode、durationMs 与关键输出摘录；对 summary 来说，是产出物清单。

reason决策理由

为什么做这一步：命中了哪条规则、依据哪些证据、为什么走这条分支。它是消除“黑盒感”的关键字段，任何一步都应能回答“为什么”。

Agent 推理

Agent 推理 vs 工具执行

Agent 推理（agent）产生计划、判断与汇总；工具执行（tool）记录真实下发的命令与原始返回。两类步骤在时间线中以不同颜色的左边框与来源徽标区分，外部事件（event）则单独标识。

工具执行

工具返回是原始证据

工具步骤展示 input 里的指令原文与 output 里的原始 payload。它们不做二次包装，便于直接对照命令、退出码与测试输出复盘。

外部事件

事件是链路起点

trigger 层记录工单来源、提交者与原始文本，是整条轨迹的输入证据；后续判断都应以它为准，而不是凭记忆复述。
